Palette proposals

Four professional directions to replace the default Ember / Chalk palettes. Each has a dark and a light variant with one shared identity. Every palette below is the full ~110-token Palette. The core roles were set by hand; the rest are derived by explicit rules in tools/palette_proposals/build.py. All of them are shown in the same app mock, with the real icons recoloured by a port of icon_theme.dart's _map.

Directions

Contrast, all palettes

WCAG 2.x ratios. Text roles must reach 4.5:1. Graphical roles (lines, glyphs, quiet states) must reach 3:1, per WCAG 1.4.11. The pair list is test/m236_theme_test.dart's, plus dim/accent on every surface, the browser's hidden-row and selected-row text, the viewport status strokes, and icon stops after _map. The Accent overrides (8 choices × panel and viewport) are folded into one row per palette.

Recommendation

Ship Graphite as the default (Graphite Dark following the system, Graphite Light for light mode). Keep Studio available as a selectable "classic" scheme for anyone attached to the teal.

  1. It fixes the actual complaint. The surfaces are neutral with a faint cool cast (saturation 3-6%), so a steel part looks like steel and nothing reads as brown. The elevation ladder is even and luminance-only: on dark, field (L* 7.7) < bg (10.3) < viewport (11.8) < panel (15.2) < fly (19.4).
  2. It agrees with the native half of the app. On the iPad, the model browser, tool bar and tab bar are UIKit glass, which already draws .systemBlue selection washes and a #007AFF root cube, with .label and .secondaryLabel text. A teal, indigo or Autodesk-cyan default leaves two accents on screen. Graphite's blue is that system blue, lifted to #4A9BFF on dark so it clears 4.5:1 on every surface, including the raised fly.
  3. Its roles make the best icons. Through _map, blue (owned), green (ok), orange (reference) and red (error) are four well-separated hues at icon lightness. All Graphite icon stops clear 3:1 on the rail. With Carbon's indigo, the darker blue-violet stops only just clear it, and Studio Light's teal face stops do not (see the note below).
  4. It passes every check. That is 0 failures in both variants, including all 16 Accent-override pairs. Chalk fails two checks today.

Runner-up: Slate, if the brand should say "Autodesk-class engineering tool" rather than "Apple pro app". Its lighter slate viewport is the most CAD-like canvas of the four. Carbon is the most striking, but it is a bigger identity change and is fussier on the iPad's glass.

Icon-mapping note, for the icon redesign. _map pins each chromatic stop's HSL lightness, not its luminance. On light schemes, that leaves hues with high luminance (teal, green, amber) brighter than hues with low luminance (blue, indigo) at the same L. On dark, the 0.32 floor leaves deep blue and indigo stops nearly invisible. That is why Chalk's and Studio Light's teal face stops come out at 2.5-2.8:1 on the rail while every blue palette passes. Since the redesign is role-based anyway, the clamp should target relative luminance (WCAG 3:1 against bg), not HSL lightness. With that change, any of these accents produces a usable set.

What changes alongside theme.dart

Where the default is chosen. In frontend/lib/theme.dart:

  • T.scheme = ValueNotifier<Palette>(kEmber) (line ~793) sets the first-frame palette.
  • T._resolved (~893) maps AppThemeMode.light/dark/system → kChalk/kEmber. The default mode is system, set by T.followPlatform() from main() and restored by T.attachStore() from AppState.init.
  • T._pushAccent() (~933) falls back to kChalk.rawAccent/kEmber.rawAccent for UIKit.
  • T.resetForTest() resets to kEmber.

Other direct references:

  • lib/backdrop.dart:209 picks kEmber/kChalk by backdrop darkness.
  • lib/settings.dart:322 defaults to palette = kEmber.
  • test/m236_theme_test.dart iterates [kChalk, kEmber] and regex-parses const Palette kChalk|kEmber.
  • The ARB strings describe Ember as "warme braune Kohle" (app_l10n.dart:814).

One semantic change. In Ember, fly is sunk on dark (#1B1815, darker than the panel). All four proposals raise fly on dark too (a lighter popover, as in macOS and Figma), and leave sinking to field, which M237 already split out. Any dark-scheme widget that still uses fly as an input well should move to field.

The toast becomes a neutral HUD (fly + hairline) in all proposals rather than Ember's amber strip. Warnings keep warn/warnText.
